# 前端 Message 反馈设计

## 目标

将 `apps/web` 中运行时错误、警告和操作结果从页面布局内的 `Alert`/`ErrorBlock` 占位迁移到 Ant Design `message`，让页面内容区保持稳定，同时保留字段校验、空状态和业务状态标签。

## 现状范围

- 查询失败在多个页面中直接渲染 `Alert` 或公共 `ErrorBlock`，部分带有布局内重试按钮。
- 登录失败和助手降级使用布局内提示。
- 市场互动失败使用布局内 `Alert`。
- 应用撤回、归档已有 `message.error`，但成功反馈未统一。
- 点赞、评分、评论、通知已读等 mutation 没有统一的成功/失败反馈。
- `Form.Item` 字段级错误、`Empty` 空状态、`Tag` 业务状态和只读说明不是运行时反馈，不迁移。

## 设计决策

### 1. 统一提示入口

新增共享 Message 反馈模块，封装错误文案提取、错误提示、警告提示和成功提示，并提供 `MessageError`/`MessageWarning` 无布局组件。组件只在状态变化时调用 `message`，自身返回 `null`，因此不会在页面中占用空间。

### 2. 查询和页面级错误

查询失败页面改为渲染 `MessageError`，移除布局内错误 `Alert`/`ErrorBlock` 和重试按钮。错误消息包含页面上下文标题与 API 错误详情；用户仍可通过页面既有导航或触发查询的操作重新加载。

### 3. Mutation 反馈

- 失败统一调用 `message.error`。
- 完成用户可感知变更后调用 `message.success`：下架、归档、点赞、评分、评论提交、通知标记已读、登录成功。
- 非阻断能力降级调用 `message.warning`：助手当前不可用。
- 互动失败改用 `MessageError`，不再在详情头部插入布局元素。

### 4. 保留的布局状态

加载中的 `Spin`/`Skeleton`、无数据的 `Empty`、状态 `Tag`、只读说明 `Alert` 和表单字段级校验继续保留，因为它们是页面内容或结构信息，不属于一次性反馈。

## 测试策略

- 为共享 Message 反馈模块增加行为测试：错误只提示一次、状态清除后同一错误可再次提示、warning/success 调用正确类型。
- 更新现有创作者中心、助手和登录测试，使其验证 Message 文案而不是布局占位结构。
- 运行前端测试、类型检查、Lint 和构建，并用源码扫描确认运行时错误分支不再渲染布局 `Alert`/`ErrorBlock`。
