# 应用管理页面 UI 设计规范

## 产品定位

`/applications` 是面向平台管理员、审核人员和应用负责人的治理工作台，用于统一查看应用状态、处理审核、管理版本和维护交付渠道。它不承担“创作者中心”的个人创作数据与成就展示职能。

## 路由结构

| 路由 | 页面职责 |
| --- | --- |
| `/applications` | 应用总览、筛选、批量治理和创建应用入口 |
| `/applications/:applicationId` | 应用详情与生命周期概览 |
| `/applications/:applicationId/versions` | 版本历史、产物校验、提交审核和版本回滚 |
| `/applications/:applicationId/review` | 审核认领、审核意见、SLA 和历史记录 |
| `/applications/:applicationId/delivery` | Web、桌面端、移动端和小程序交付配置 |

创建应用使用 `/applications` 页面内抽屉，不新增独立路由。

## 视觉方向

- 设计模式：企业级治理总览工作台。
- `DESIGN_VARIANCE`：4。
- `MOTION_INTENSITY`：3。
- `VISUAL_DENSITY`：7。
- 主色：`#1677ff`。
- 页面背景：`#f5f7fa`。
- 标题区背景：`#eaf3ff`，允许使用低对比度技术几何纹理。
- 主文字：`#111827`；辅助文字：`#64748b`；边框：`#e5e7eb`。
- 内容面板统一 16px 圆角，按钮、输入框和选择器统一 8px 圆角。
- 仅在需要表达层级时使用冷蓝色柔和阴影。

## 主页面布局

1. 复用现有应用外壳，左侧导航高亮“应用管理”。
2. 顶部栏不展示应用市场搜索框，只保留通知、帮助和用户信息。
3. 浅蓝标题区展示“应用管理”、治理说明和“创建应用”主按钮。
4. 概览指标展示应用总数、待审核、已上架和交付异常。
5. 主面板顶部提供“全部应用”“待我审核”“我负责的”三个视图。
6. 筛选条包含关键词、状态、所属部门、应用类型、交付渠道、更新时间排序和重置。
7. 应用表格展示应用名称、状态、当前版本、负责人及部门、交付渠道、最近更新和操作。
8. 底部展示总数、分页和每页数量。

## 状态和操作

- 已上架：绿色弱底标签。
- 审核中：橙色弱底标签。
- 草稿：中性灰标签。
- 已下架：红色弱底标签。
- 操作根据状态展示“查看”“版本”“审核”“继续编辑”“重新发布”“更多”等入口。
- 删除、下架、重新发布和版本回滚等敏感操作需要二次确认。

## 响应式规则

- 桌面端使用完整表格和一行筛选条。
- 平板端允许筛选控件换行，并隐藏次要表格列。
- 移动端将表格切换为信息分组列表，保留状态、负责人、版本和主要操作。
- 创建应用抽屉在移动端全屏显示。
