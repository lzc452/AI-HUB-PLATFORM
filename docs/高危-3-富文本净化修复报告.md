## 四、本次实际修复：关闭前后端唯一不一致

发现前端 DOMPurify 默认行为与后端白名单存在一处差异：

1. DOMPurify 默认 `ALLOWED_URI_REGEXP` 仍放行 `data:` URI（如 `data:image/svg+xml`），后端已禁止 `data:`；
2. 协议相对地址 `//host` 默认放行。

### 改动 `apps/web/src/shared/ui/sanitize.ts`

- `ALLOWED_URI_REGEXP` 增加负向先行断言 `(?!\/\/)`，在正则层拒绝协议相对地址。
  - 注：DOMPurify 3.2.4 **无** `allowProtocolRelative` 选项（源码确认），旧写法 `allowProtocolRelative:false` 无效，已移除。
- 新增 `uponSanitizeAttribute` 钩子，显式丢弃 `href`/`src` 上的 `data:` 与 `//`：
  - DOMPurify 的 `DATA_URI_TAGS` 解析仅支持"追加"（`ADD_DATA_URI_TAGS`），**无法从默认集合移除 `img`**，因此 `data:` 的禁用必须用钩子兜底（源码确认 `keepAttr=false` 会移除属性）。

```ts
const RICH_TEXT_ALLOWED_URI_REGEXP =
  /^(?!\/\/)(?:(?:(?:https?|mailto|ftp|tel|file):|[^a-z]|[a-z+.\-]+(?:[^a-z+.\-:]|$))|(?:&(?:#\d+|#x[a-f0-9]+|[a-z0-9]+);))/i;

DOMPurify.addHook("uponSanitizeAttribute", (node, data) => {
  if (data.attrName === "href" || data.attrName === "src") {
    const value = String(data.attrValue ?? "").trim().toLowerCase();
    if (value.startsWith("data:") || value.startsWith("//")) {
      data.keepAttr = false;
    }
  }
});
```

后端 `content-security.ts` 本身已健壮（`data:` 经 `isSafeUrl` 拒绝、`//` 经 `allowProtocolRelative:false` 拒绝），本次未改动，仅补测试。
